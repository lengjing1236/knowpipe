## 质量结论：尚未达到可依赖的教学阅读标准

已人工阅读本地保存的两组完整文字稿和中文译文。加入元数据提示后，部分云服务名称的英文拼写更接近发布方内容；但这是一条样本上的工程对照，提示词来自同一期标题，不能算独立识别准确率。

仍然存在实质问题：

1. tiny 模型误识部分术语和普通词组，上下文提示不能全部修复；加提示的版本还漏掉了节目末尾的主持人结束语。`complete=True` 表示整段音频已经处理，不能解释为逐字无遗漏。
2. Argos 会把技术专名译成不自然的普通词，还会误译成本变化、容器等技术概念，个别短句不可理解。上下文连贯后部分可读性改善，但整体仍不可靠。
3. 自编数据库样本中的事务与回滚被译成非标准术语。这个问题来自真实输出，证据保留原结果，没有人工修正后冒充模型产出。
4. 没有独立逐字标签或双语质量标签，因此没有编造 WER、翻译准确率或教学有效性分数。节目文字稿和译文仅保存在被 Git 忽略的本地缓存，仓库记录来源、哈希和有限质量观察。

建议把当前输出明确标为自动转写/自动译文并保留原文对照；在真正交付学习用户前，需要更强模型或经用户授权的服务，并在未用于调试的计算机材料上重新评价术语、数字、否定条件及漏译。当前完成的是可替换、可复现的处理流程和免费基线，不是内容质量终点。

## 推荐列表真实翻译失败的只读复核

2026-09-25，复核万条语料验收库中已执行的推荐翻译。该次 10 篇入选资料有 2 篇原生中文；8 篇英文各尝试翻译 1 次，6 篇状态为 `ready`，2 篇为 `failed`。这只是一次运行结果，不能当作翻译准确率或总体成功率；`ready` 也不代表译文已通过内容质量评价。

- `softwareengineering-444712`（[Is it needed a unit of work with DDD?](https://softwareengineering.stackexchange.com/questions/444712/is-it-needed-a-unit-of-work-with-ddd)）：问题及 3 个答案的完整正文，语言 `en`，共 7,079 字符/UTF-8 字节；按当前切分逻辑得到 49 个可译片段、74 个句子，最大句子为 48 个 SentencePiece token，低于单块 192 token 和全文 4 MB 限制。原文含围栏代码及 `ie` 等独立短片段。失败记录是 `translation_failed`，没有部分译文落库。输入大小、全文缺失或不支持英语均不能解释这次失败。
- `stackoverflow-80003232`（[Postgres row-level security leaks across tenants when using a pooled connection](https://stackoverflow.com/questions/80003232)）：同次运行也记录 `translation_failed`，不能在验收结论中写成全部英文翻译成功。

当前适配器会拒绝没有结束标记的输出及空译文，任何片段失败都会使整篇失败，避免把部分译文标成全文完成。该次运行时，公共调用层把非配置类异常统一保存为 `translation_failed`，没有保存具体异常类别或失败片段编号；仅凭这些历史记录，**无法确认这两篇究竟触发空输出、截断保护还是其他运行异常**。独立短片段造成空输出只是假设。此次诊断仅查阅数据库、代码和运行本地分词器，没有重新推理、重试或修改原始数据，也没有把失败归因于已经验证的截断。

后续诊断应在不记录原文和敏感异常消息的前提下保存受控错误码、片段序号及 token 数，再针对失败材料验证；应继续保留失败状态及原文入口，不通过跳过失败片段或原文冒充中文来提高成功数。

已补齐有限错误码映射：仅对已知异常类型及精确标识符保留空输出、未完成输出、截断、超时、无效输入/输出、模型不可用和语言不支持的类别；未知异常仍使用通用码，不保存异常原文。回归验证了不完整结果不会发布、未知异常不会泄露信息。这项改动帮助诊断后续运行，不改写上述历史失败原因，也没有提高或宣称提高模型质量；片段序号及 token 数尚未保存。
