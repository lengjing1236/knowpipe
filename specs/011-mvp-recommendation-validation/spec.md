# Feature 011：核心推荐 MVP 的需求与效果验证

日期：2026-09-25。状态：[方案] 验收门槛先于实现冻结；执行结果另记，不因失败降低门槛。

输入依据：用户要求按根目录 plan.md 并行开发，用 Spec-Kit 落实 MVP，先验证算法是否满足实际需求，规模扩展后置。支持广泛计算机技术；四主题仅是验证样例。

## 用户故事与独立验收

### US1（P1）：推荐能帮助完成中文学习目标

作为有一定基础的学生，输入中文技术学习目标后，我希望看到正文真正讲解该问题的材料，资料不足时明确告知。

1. 无历史、有合适资料：返回能回答目标的正文证据；标题、目录、技术名出现本身不是通过依据。
2. 相同词汇但错误技术对象／问题：不以低历史重合或新词多为由推荐。
3. 有限资料库没有合适资料：允许空列表，不凑满数量，不宣称整个互联网没有答案。
4. 中英文等义目标：不因翻译改变技术对象、关系与问题范围；失败应可见。

### US2（P1）：已读资料改变下一步阅读选择

作为学生，主动标记已读资料后，我希望优先看到对当前目标有具体补充的内容，知道哪些内容与已读重合、哪些可能值得继续阅读。

1. 同一目标、覆盖内容不同的历史：在确有不同补充材料时，排序或候选补充证据产生合理变化。
2. 转载、同义改写：不能把换词当补充。来源不同也不自动证明互补。
3. 部分重复、部分新方法：保留可核对的新内容；补充价值实际参与排序，而非只改理由。
4. 历史无关、过期或不可比较：仅给目标推荐并说明比较不足，不断言“用户未知／已掌握”。
5. 每项候选补充结论均有目标相关性、候选原文、相关历史原文及对应位置；不把模型预测包装为已证实知识增益。

### US3（P1）：理解中文全文及推荐依据

选入列表的英文材料自动准备完整中文阅读，保留原文，并能核对段落。数字、代码、术语以及关键条件／因果／先后关系不得因翻译产生错误教学含义。模型失败、无法比较、未完成翻译须显式展示；输出完整或无数字损坏不代表语义正确。

### US4（P1）：真实 Web 操作闭环与新增材料

从网页保存目标，真实后台计算，再展示推荐及中文阅读；显式标记已读后重新计算。新增资料（包括 RSS 转写全文）用同一策略判断：相关补充可通知，重复或无关不能伪装成补充。通知不等于阅读，不产生重复未读通知。

## 功能要求

- FR-001：保留多源全文、来源、版本、原文偏移和显式已读语义；保留四层 Web 架构与真实 Spark 核心计算。
- FR-002：相关性先于差异性。正文必须支持学习目标，纯标题不得充当教学证据。
- FR-003：支持有界语义比较，区分已覆盖、候选补充、比较不确定；不能仅靠未出现词或整篇相似度给出补充结论。
- FR-004：覆盖惩罚、候选补充证据、列表去重实际参与最终选择。保留无历史、无去重和词汇基线供对比。
- FR-005：比较范围和限制可追溯。未比较全文不能声称全文无重合，模型失败不能退回词汇“补充”通知。
- FR-006：中文目标和中文正文必须真实处理，不能把中文静默喂给不支持中文的模型再声称多语能力。
- FR-007：选中英文全文自动翻译；对齐只能来自真实翻译过程，旧数据无对齐不得伪造。质量检查与人工／语义验证分别标识。
- FR-008：模型、参数和处理规则改变使缓存／任务身份失效；旧工作者不得覆盖新版本结果；沿用租约及版本保护。
- FR-009：新增材料、普通推荐及 RSS 通知复用同一补充决策；版本变化和重试不造成重复未读通知。
- FR-010：验收通过真实 Web→业务→Mongo／挖掘→Spark→语言处理→API→Web 完成；注入离线推荐结果只能算展示测试。
- FR-011：实际评估冻结输入、原文事实、语料摘要、处理版本、失败原因和基线；标明代理编制案例，不冒充独立人类学习效果实验。
- FR-012：所有语义与翻译计算有资源／输入边界，长文本分段或明确不可比较，不能静默截断后宣称完整验证。

## 成功标准（先行冻结）

[方案] 以下为此次有限 MVP 验收，不代表对任意计算机主题保证准确率。案例预期由来源事实支持，与算法输出独立。

- SC-001：至少四个技术主题，每个包含无历史、有限历史、覆盖充分历史；每个明确有合适材料的场景 top3 至少一条直接帮助目标的材料，全部已判定 top3 结果相关率至少 80%。未判定结果单列，不能自动算相关或无关。
- SC-002：冻结的转载／同义复述、无关新词、错误对象、无资料场景中，错误“补充”结论为 0；有具体补充的每个场景至少给出一条双方证据支持的候选补充。不能靠全部拒绝通过。
- SC-003：冻结的部分补充和不同历史案例中，证据及优先项合理变化；消融证明确有覆盖／补充／去重作用，若无收益需保留失败，不把分数变化当收益。
- SC-004：冻结中文目标与完整英文技术资料中关键技术事实、条件及顺序不发生实质错误；逐条展示原文与输出复核。数字／代码检查仅是必要条件；至少一篇真实英文全文走完整中文阅读。
- SC-005：至少一条真实浏览器闭环完成目标→计算→阅读→显式已读→重算，无伪造 ready job；新增相关补充／重复／无关三个分支验证通知决定，包含至少一条真实 RSS／音频转写链路，报告音频与转写本身的局限。
- SC-006：小案例在既有万条背景语料中复验，不以只保留标准答案的候选池冒充全库效果。至少两个预先冻结且未用于算法调参的保留场景，单独报告；旧 010、CQADupStack 已观察案例只能算回归。

## 边界与假设

[已确认] 只有一台电脑，使用本机 Spark；跨主机部署、进一步扩大语料、长期订阅吞吐不在此次开发范围。现有万条语料继续作干扰背景。

[已确认] 学习历史仅由主动已读产生，读过不等于掌握；取消此前人工批量标注任务，不要求用户重做。笔记、问答、视频／BV 输入不是本次新增范围。

[方案] 本次用代理根据原文整理有限案例及事实对照。没有独立用户实验时，不声称学习提升已获实证。预算使用本地开源 CPU 模型，无付费服务；模型不可用或质量未达标时应记录失败。
