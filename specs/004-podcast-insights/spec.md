# Feature 004：播客订阅与文字稿知识加工

日期：2026-09-16。状态：[已验证] 本轮实现与本机验收完成；[待确认] 外部/业务验收见 tasks.md。

## 用户故事

P1 用户订阅公开 RSS，看到节目更新和处理状态；有文字稿时得到全文、分段关键词、主题分组与相关片段，并收到站内通知。
P2 评审查看每次处理的 Spark application id、批次、输入分段数、耗时、来源链接，理解从原始文字到分析结果的过程。
P3 用户可取消订阅并只查看自己的通知，不泄露其他人的订阅记录。

## 功能规约

- POD-001：注册用户添加/查看/取消个人 RSS 订阅；重复订阅幂等。公开 feed 共享采集，用户关系分开存储；每人最多 20 个订阅。
- POD-002：独立 worker 默认每 300 秒轮询；首次只处理最新 3 集，限制历史回填规模；节目以 feed_id + GUID（缺失时 enclosure/link）稳定去重。
- POD-003：优先支持 Podcasting 2.0 transcript 的 text/plain、SRT、VTT、JSON；不把节目简介冒充全文。缺失文字稿标记 awaiting_transcript 并保留来源链接，不能标记完成。
- POD-004：已订阅用户可为 awaiting_transcript/failed 节目提供自有文字稿；标记 user_supplied 来源。自动音频转写作为后续可选扩展，先确认中文播客、费用和运行硬件。
- POD-005：文字稿分段后由真实 Spark 执行 TF-IDF、主题聚类和相似片段检索；支持中英文分词；不足以聚类时显式标记降级，不伪造簇。结果簇只在本批次有效，不与历史文献簇 ID 混用。
- POD-006：处理状态 queued → processing → ready / awaiting_transcript / failed。保存有限重试次数、下次重试时间与错误代码；进程退出后租约过期可恢复；相同节目重复处理不产生重复通知。
- POD-007：站内通知通过认证的 SSE 连接推送；断线恢复通过持久通知列表，支持标记已读。处理完成到已连接页面通知的目标延迟 ≤10 秒，发现更新目标 ≤5 分钟 + 排队/处理时间；这些是验收目标而非硬实时承诺。
- POD-008：RSS/文字稿每次连接与重定向校验公共 HTTP(S) 地址，拒绝内网/回环/metadata/带凭据地址；连接固定到已验证 IP，限制响应大小、超时和重定向。
- POD-009：RSS 和文字稿下载均上限 4 MiB，文字稿解析后仍不超过 400,000 字符，单集最多 500 段，首版只启动一个有租约保护的 worker；过大输入明确失败，不静默丢字。2026-09-16 为接入约 2.27 MB 的真实 JS Party RSS 调整下载上限。
- POD-010：支持 RSS 显式声明的 HTML 官方文字稿，只提取发言者和段落，排除脚本、导航等；不将节目简介当作文字稿。免费隧道不支持 SSE 时，通过每 5 秒读取持久通知兼容。
- POD-010：每个成功产物附 batch_id、Spark application id、Spark master、段数、开始结束时间与原文来源；失败也有批次记录。

## 验收场景

重复轮询同一 RSS 只产生一集记录和每用户一条通知；两用户订阅/取消互不影响；未登录 API/SSE 返回 401。
内网 URL、重定向内网、XXE、超大输入被拒绝；缺失 transcript 不产生 ready 通知。
真实 Spark 对中英文及单段输入运行，产物可查证；重试/租约恢复不重复通知。
[待确认] 实际播客 RSS、希望自动转写的语言与部署资源；站内通知作为默认首版，邮件必须另行明确授权与配置。

## 答辩增值点

[方案] 首版以“订阅增量数据→批处理知识加工→可追溯通知”为主线。
后续优先级：跨节目主题趋势（按周聚合）、知识掌握反馈、播客与技术文献关联、人工 Precision@K/NDCG 对比。
这些功能必须基于可复现数据；未实现时不得画在“已完成”架构里。

## 开发中澄清（2026-09-16）

[方案] 当某段 TF-IDF 全零时，仅该段的关键词展示改用词频，并记录 keyword_weighting；相似度仍使用实际向量，无有效信号不输出相似片段。全体向量全零时整批采用显式标记的词频向量；单组不伪称多主题聚类。
[方案] 首次回填 3 集；后续每次最多检查 feed 最近 100 集。RSS 上游不再提供的历史节目无法补采，页面/文档需说明。
