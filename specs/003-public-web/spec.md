# Feature 003：公网 Web 与答辩可用性

日期：2026-09-16。状态：[已验证] 本轮实现与本机验收完成；[待确认] 外部/业务验收见 tasks.md；验收状态独立记录，部署配置不等于已上线。

## 目标与用户故事

- P1：访客从公开 HTTPS 地址注册、登录，无需手工传 user_id，即可操作自己的画像和查看推荐。
- P1：维护者用同一份容器配置启动 Web、持久化 MongoDB 和反向代理；重启后账户与业务数据保留。
- P2：评审通过页面查看真实数据规模、来源分布和最近 Spark 批次，区分成功、失败与尚未运行。

## 功能规约

- WEB-001：会话身份由服务端确定，新增 GET /api/auth/me；页面登录后自动初始化，不从 URL 获取身份。
- WEB-002：生产环境必须配置至少 32 字符的非默认 SECRET_KEY、公开 HTTPS 地址；禁用 debug，使用 Gunicorn。
- WEB-003：所有修改 API 使用 CSRF token；生产会话 Secure、HttpOnly、SameSite=Lax；设置请求体上限、CSP 与安全响应头。
- WEB-004：身份字段必须是字符串，用户名 1–64 字符、密码 8–256 字符；非法 JSON 结构返回 400，避免 Mongo 查询注入。并发重复注册返回 409。
- WEB-005：生产登录/注册请求使用 Mongo 原子计数限流，跨进程生效；默认每 IP 每分钟 20 次（固定窗口，边界突发最多两倍）；超限 429 + Retry-After。
- WEB-006：GET /health/live 只报告存活；GET /health/ready 检查数据库，不回显连接串；GET /api/stats 展示来源数量和脱敏批次摘要。
- WEB-007：浏览器明确显示加载、空数据、鉴权失效与请求错误；推荐可查看正文、来源、评分和分类依据。
- WEB-008：生产 Compose 只公开 Caddy 的 80/443；MongoDB 启用密码并使用持久卷，Web 和数据库不映射宿主机端口；Spark 计算与 Web 进程分离。

## 验收场景

1. Given 新账户，When 登录并进入首页，Then 无 URL 参数即可加载主题、提交画像、查看推荐。
2. Given 无 token/他人 session/字典型用户名，When 提交修改请求，Then 分别返回 403/401 或 403/400，数据库不改变。
3. Given 生产配置缺失，When 启动，Then 明确拒绝；正确配置返回 Secure cookie，响应无堆栈和秘密。
4. Given 同 IP 并发登录尝试，When 超出窗口额度，Then 多进程共享计数并返回 429。
5. Given Mongo 不可用，When 探测 readiness，Then 503；存活探测仍可报告进程状态。
6. Given 有真实批次，When 进入页面，Then 统计来自 Mongo；无数据不得显示伪造的万条成果。

## 成功标准与边界

[方案] 自动化契约/安全测试通过，原有测试不回归；生产 WSGI 本机真实 HTTP 冒烟通过。
[待确认] 服务器、域名、DNS 与预算决定实际公网验收；必须从外部网络访问 HTTPS 才能标记“已上线”。
[课程要求] 至少万条主源数据、Spark 运行证据与真实人工评价另行验收，不以 Web 测试代替。

[方案] WEB-009：推荐接口 limit 限制为 1–100，避免公开客户端请求无界结果集。
