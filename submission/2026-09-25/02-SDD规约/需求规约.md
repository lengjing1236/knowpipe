# Knowpipe 多源计算机技术资料推荐系统：需求规约

日期：2026-09-25。适用对象：课程提交版。本文汇总现行需求，不改写历史 Spec 的验收门槛；演示交付由 `specs/012-demo-delivery/` 管理，推荐质量验证由 `specs/011-mvp-recommendation-validation/` 管理。

## 1. 用户、问题与产品边界

[已确认] 主要服务有一定基础、围绕具体技术问题持续学习的计算机专业学生。用户输入中文学习目标，系统从多源技术全文中找出有帮助的材料，并参考用户主动标记的已读资料，展示重合、可能的补充及原文依据。

“多源”指问答、官方文档、教程、研究全文和播客转写等不同原始内容来源进入同一分析流程；同一内容在不同平台的镜像不算独立来源。“个性化”指当前目标和版本化已读记录参与选择，不是为所有人显示同一热门榜。读过不代表掌握，模型不能证明某知识点对用户一定未知。

系统支持广泛计算机技术；PostgreSQL、Python、Docker、Django只是本轮验证主题，Pandas不是产品范围上限。当前只有一台电脑，先验证正确性，再决定是否扩展为跨主机集群。笔记、通用问答、视频/BV输入不作为本次新增交付承诺。

## 2. 功能需求与验收依据

| 编号 | 必需行为 | 验收方法与当前事实 |
| --- | --- | --- |
| R01 | 多源文档统一保存来源、完整正文、语言及版本 | 检查真实MongoDB记录；10,215篇背景用于011评价。摘要不能冒充全文 |
| R02 | 用户可注册登录、保存中文目标；数据按会话身份隔离 | 真实页面与API检查，不能以浏览器传入任意user_id跨账户访问 |
| R03 | Spark实际从语料召回并计算选择结果 | worker运行日志、索引清单和真实结果；不能注入ready job作为生产计算证据 |
| R04 | 正文直接服务目标；错误对象、无关新词不能仅因差异大而获推荐 | 011预冻结四主题案例；当前相关性标准未通过 |
| R05 | 仅主动已读进入历史；记录正文版本，支持取消已读 | 保存目标与已读变更使任务身份更新；通知已读不等于文档已读 |
| R06 | 区分重合、可能补充和无法比较，给双方原文位置 | 011逐条原文审核；同义复述不应计新知识，当前仍有误报 |
| R07 | 入选英文资料自动准备中文全文，保留原文和真实段落对照 | 显示处理状态与失败原因；不能用短摘要代替全文，不能把结构检查当语义正确 |
| R08 | RSS新节目获取音频、转写全文、入库并进入同一推荐策略 | 真实公开音频链路已完成ASR与入选；中文就绪通知闭环尚未通过 |
| R09 | 只有符合推荐条件、中文就绪、任务和订阅仍有效时通知 | 验证相关补充、重复、无关三分支及幂等；三分支实际回放未完成 |
| R10 | 页面呈现原文依据、状态和比较范围；资源不足或模型失败不伪造成功 | 完整/部分执行分开标识，降级结果不得宣称已证明补充 |
| R11 | 需求、设计、任务、代码和验证证据可追溯 | Spec-Kit目录、Git提交、输入/输出哈希、提示词归档和本次六项交付 |

## 3. 质量门槛

[方案：验收前冻结] 011要求至少四主题的无历史、部分已读及充分已读场景；每个正例top3至少一条直接帮助，已判定top3相关率至少80%。转载、同义复述、无关或错误对象不能产生错误补充，同时真实补充不能全部被拒绝。不同历史和消融应证明合理变化。中文关键条件、顺序和技术事实应正确，且真实页面完成阅读、已读与重算。

[已验证：未通过] 最终17案中35个返回项有13个直接有帮助、13个部分相关、9个无关，直接率37.1%；即把部分相关宽松计入也仅74.3%。发现11条错误补充与12条证据不足。故演示版能运行并不等于上述产品效果已达标。

## 4. 非功能约束

- 存储使用真实MongoDB，核心文本处理和评分使用真实PySpark；本机`local[1]`不得描述为跨主机集群。
- 全文、已读、翻译、索引及任务绑定内容版本和处理身份；重试不生成重复通知，旧任务不得覆盖新状态。
- 模型计算有明确预算。超出范围应标示未比较，不得截断后声称完整分析。
- 凭据通过环境变量等本机配置提供，不进入源码、提示词归档、截图或视频。模型权重与运行数据不强行放入Git。
- 远程免费模型是用户最新翻译方向；具体provider的可用性、配置和实际演示结果按012证据记录，不沿用本地Qwen通过的假设。

## 5. 本次可录屏版本的独立范围

[已验证：012工程流程] 使用12篇原生中文官方全文（Python 7篇、Django 5篇），完整导入独立`knowpipe_demo012`数据库；Web地址`http://127.0.0.1:8019`，MongoDB端口27018。通过真实页面演示登录、保存目标、Spark推荐、中文阅读、主动已读及重算。真实网页已完成目标、推荐、阅读、主动已读及重算：已读数为1，修订号2的新任务就绪，已读Django事务资料被排除。重算语义状态为partial，首轮仍存在相关性问题，工程通过不等于推荐质量通过。

原生中文资料可直接阅读，无须调用翻译。本次不通过人工替换译文或伪造ready结果绕过011失败。免费远程provider默认模式为`bigmodel-free`；鉴权失败时英文内容显示不可用，不启动本地模型或收费回退。用户已有并配置远程凭据，但3个官方技术段落与1个中文目标的4次实际调用均返回HTTP 401，无译文可供质量验收；当前应表述为鉴权未通过，而非没有密钥。

六项提交为：源码Git URL与真实历史；需求/设计规约及可核实的Vibe Coding提示词Markdown；项目报告；不超过5分钟的MP4演示视频；最终分工表；可编辑PPT。演示范围小不改变产品支持广泛计算机技术的目标，也不将产品收窄为Pandas学习工具。

## 6. 需求变更依据

初版将关键词/主题簇映射为known/new等类别，并以问答正文和论文摘要组织数据。后续用户明确要求广泛计算机主题、全文中文阅读、主动已读和RSS音频；当前规约据此将重点转为目标相关性与有依据的材料补充。旧宪法中的掌握判断、摘要来源限制属于历史假设，011计划已记载差异及理由。

用户最新要求优先形成可录屏演示版本和六项提交材料。012的演示范围不能降低011质量标准，也不能把未完成的验证改写为已通过。真实用户提示词及覆盖范围见本目录`提示词归档/`。
