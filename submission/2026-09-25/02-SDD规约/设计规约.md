# Knowpipe：设计规约

日期：2026-09-25。依据：现行源码、007—011 Spec及对应证据。012交付封装的实际配置与演示结果以其规约和提交包运行说明为准。

## 1. 四层架构与数据流

```text
浏览器：中文目标、推荐列表、原文/中文阅读、主动已读、RSS与通知
  ↓ HTTP（Flask）
业务层：会话鉴权、目标/历史变更、队列调度、worker租约、翻译与通知门控
  ↓ 版本化数据与分析请求
数据管理与挖掘层：MongoDB全文/用户历史/任务/结果/缓存；语义比较规则
  ↓ 真实DataFrame/MLlib作业
Spark处理层：索引、全库候选召回、历史筛选、特征聚合、覆盖/补充/去重选择
  ↑ 结果回存MongoDB → API轮询 → 页面显示

RSS → 发布方文字稿或音频ASR → 完整文本入库 → 同一worker与推荐流程
```

层次按职责划分，不声称已部署为四个独立微服务。Web进程负责响应请求，独立worker承担Spark及长任务，避免在一次HTTP请求中阻塞全文计算。MongoDB是业务事实存储，JSONL/Parquet用于导入、快照和索引工件，不取代数据库。

## 2. 技术选型与理由

| 组件 | 选择 | 对应原因及边界 |
| --- | --- | --- |
| 页面/API | Python、Flask、服务端模板、浏览器JS | 复用已有鉴权和页面，适合有限课程周期；后台计算异步化 |
| 数据管理 | MongoDB | 来源异构、正文与处理状态是半结构化文档；支持复合索引、版本更新与任务状态查询 |
| 文本处理 | PySpark DataFrame/MLlib | 实际完成词汇索引、候选计算、聚合和自定义选择；本次使用单机真实Spark |
| 语义特征 | 多语相关性/向量模型、方向性NLI | 补足纯词汇匹配，但预测可能误判；有预算、状态和原文依据，不能宣称理解掌握程度 |
| 中文与ASR | 可配置翻译provider、faster-whisper | 提供阅读与文本输入能力；属于辅助环节，不替代核心Spark挖掘 |
| 过程与验证 | Spec-Kit、Git、轻测/真实集成/冻结案例 | 把需求、实现存在和效果通过分开记录 |

## 3. 推荐算法与计算边界

1. 保存中文目标及显式已读记录，生成绑定用户输入、内容快照和处理器版本的任务。
2. Spark通过全文词汇索引宽召回，按技术对象和正文说明内容过滤；已读版本不匹配时说明历史不可用。
3. 对最多100篇候选、合计300段正文进行有界分析，扩展同文档邻近上下文；不会为全库构造大模型向量。历史与句对另有预算，超限明确记录。
4. 多语模型直接处理原中文目标相关性；候选陈述与相关历史段落做相似/蕴含比较。模型特征在driver侧有界产生，不冒充Spark分布式模型训练。
5. Spark聚合相关度、历史覆盖和候选补充特征，并通过UDF执行最多3项贪心选择。当前规则的基础分为`相关度×(1−0.6×覆盖度)+0.4×补充分`；启用多样性时再取`0.85×基础分−0.15×与已选最大相似度`，高重复项跳过。该规则借鉴覆盖/MMR思想，不声称原创理论算法。
6. 输出当前目标依据、候选与历史双方原文、版本与字符偏移、比较范围及失败状态。缺少语义能力时可显示词汇目标匹配，但禁止声称补充和发布补充通知。

`without_history`与`without_diversity`是同一固定候选集合上的重排对照；它们不是去掉历史后重新执行全部召回、翻译、语义比较的完整消融。

## 4. 主要数据实体

| 实体/集合 | 关键内容 | 约束 |
| --- | --- | --- |
| `documents` | source、doc_id、source_url、body_text、language、content.version、processing、translation | 来源与文档ID区分身份；全文/译文/原文偏移必须对应同一版本 |
| `user_profiles` | 用户目标、输入修订号、版本化已读记录、期望任务 | 只允许本人会话修改；打开网页不自动算已读 |
| `recommendation_jobs` | 目标/历史快照、语料与处理身份、状态、租约、结果 | 已过期任务不能覆盖当前结果，重算可追踪 |
| `recommendation_runtime` | 当前语料索引、worker租约、处理generation | 避免多个worker竞争发布和旧模型覆盖 |
| `podcast_feeds` / `podcast_episodes` | RSS地址、节目ID、发布时间、音频/稿件地址、处理状态 | 重复轮询幂等，真实文字稿与ASR来源可区分 |
| `notifications` | 用户、节目、版本、当前推荐依据 | 订阅/任务有效且符合资格、中文就绪才发布，不重复创建未读通知 |

## 5. API契约摘要

当前学习接口位于`/api/learning`，统一需要登录，并由会话确定用户身份。

| 方法/路径 | 行为 |
| --- | --- |
| `PUT /goal` | 接收1—1000字符目标，更新输入版本并触发后续任务 |
| `PUT /read-state` | 显式设置/取消已读；设为已读必须带正文版本，版本变化返回冲突 |
| `GET /document`、`GET /documents` | 原文/中文/状态详情与分页检索；文档ID使用参数而非不安全路径拼接 |
| `GET /history`、`GET /profile` | 查询本人的历史与目标状态 |
| `GET /recommendations` | 查询当前任务与结果；排队/运行/失败/就绪清晰呈现 |
| `POST /recommendations` | 空对象请求重新计算，返回202 |

非法输入、未登录、内容变化和不存在资料分别走可见错误响应，不伪造推荐成功。

## 6. 中文、RSS与故障处理

英文资料一旦入选即自动准备完整中文，不要求用户再点击“请求翻译”。翻译必须保留可定位原文及真实段落对应；质量检查包含结构、标识符与数字等，但不能保证技术语义正确。处理身份变化使旧缓存失效，生产重试按版本和processor计数。011本地候选存在实质误译，用户最新要求改用免费远程模型；配置和实测结果在012另记，不暗中降门槛。

RSS发布方无文字稿时，可从完整音频进行ASR。临时音频处理后清理，转写全文以`podcast`文档进入统一索引。ASR成功并入选不代表个人补充已被证明；通知需同时满足补充资格、当前任务/订阅和中文就绪。失败与等待重试必须区分，首次失败不能描述为最终耗尽。

## 7. 验证与部署取舍

011先冻结17案和原文事实，再运行开发案例及保留场景；13案使用10,215篇完整背景，4案为明确受控池。所有35个返回项完成代理原文审核，348个来源/版本/偏移字面校验通过；字面无误不能抵消语义失败。核心产品质量仍未通过。

真实浏览器、MongoDB、worker与Spark走工程验收；静态截图只能证明展示。录屏采用真实应用和真实可复用处理结果时，应说明准备阶段和数据范围，不能把准备好的页面说成实时全库重算。

本机Spark可验证计算与逻辑。跨主机Spark在数据/任务足够大时有望提高容量和吞吐，但通信和调度也有开销，不保证小任务更快；不会自动修复相关性、补充误判和翻译语义。当前应优先解决质量，之后再以同输入、同算法比较资源利用和耗时。
