# Feature Specification: 中文目标匹配与计算部署准备

**Feature Branch**: `010-quality-cluster-readiness`
**Created**: 2026-09-25
**Status**: [已实现：阶段A工程机制与有界验收] 翻译教学质量、全部主题相关性及跨主机部署未达标，见总体plan后续阶段。
**Input**: 对照总体 plan 和 009 验收，说明未满足需求、改动理由及分布式影响，使用 Spec-Kit 开始执行。用户确认目前只有一台电脑。

## User Scenarios & Testing

### User Story 1 - 用中文描述学习目标 (Priority: P1)
学习者使用自然中文目标寻找中文或英文原始资料，无需自己补写英文关键词。
**Why this priority**: 现有中文目标可能因为语言差异返回空，直接阻断主要用户。
**Independent Test**: 固定多个计算机方向的中文及英文对应目标，运行实际语言转换和真实全文检索，分别记录命中与失败；不把开发样例当独立效果标签。
**Acceptance Scenarios**:
1. Given 中文目标，When 生成推荐，Then 保留原目标，同时展示用于查找英文资料的解释，原中文资料仍可被检索。
2. Given 语言转换不可用或失败，When 检索，Then 保留原文查找并说明跨语言功能未就绪，不把失败解释为资料库没有相关知识。
3. Given 同一目标及相同转换版本，When 重复计算，Then 复用解释；转换版本更新后旧推荐不冒充新结果。

### User Story 2 - 推荐遵守明确的技术对象 (Priority: P1)
用户指定 PostgreSQL 等技术对象时，结果不能只因“事务”等泛词匹配，就推荐完全没有涉及该对象的资料。
**Why this priority**: 上一验收出现 PostgreSQL 目标下首推泛 Spring 事务问题。
**Independent Test**: 在含相似泛词但技术对象不同的资料中，验证显式技术名称及别名约束；无具体对象的目标保持可用。
**Acceptance Scenarios**:
1. Given 明确产品名或代码式名称，When 召回，Then 结果存在该对象的正文或标题依据，并解释约束。
2. Given 两种资料仅有相同泛词，When 具体对象不匹配，Then 不作为同对象推荐发布。
3. Given 候选不足，When 返回较短列表或空，Then 说明实际筛选与语言状态，不声称用户已经掌握。

### User Story 3 - 知道译文从何而来及哪些内容需复核 (Priority: P1)
学习者能看到自动译文的来源版本、数字及代码完整性检查和局限；升级翻译服务后能重新生成旧版本译文。
**Why this priority**: 当前成功状态未说明模型身份，数字、技术名词可能误译。
**Independent Test**: 使用含数字、百分比、代码及技术名词的固定文本检验完整处理与风险显示；真实模型结果单列，不以规则通过证明语义正确。
**Acceptance Scenarios**:
1. Given 自动译文，When 阅读，Then 可查看原文和有限质量信息，明确未经人工复核。
2. Given 已发现数字或代码遗漏，When 发布，Then 不将有该缺陷的结果作为中文就绪内容推送。
3. Given 翻译实现版本改变，When 再处理，Then 不静默复用旧模型输出；只有原版本对应的完整结果可被发布。

### User Story 4 - 分清计算部署与推荐质量 (Priority: P2)
开发者能使用同一份数据和相同规则比较本地与独立计算进程执行结果，并获得未来跨主机运行的准备检查。
**Why this priority**: 当前本地路径与配置不能证明系统可直接部署到多主机；课程也要求真实证据。
**Independent Test**: 运行本机独立执行进程的有界验收，记录实际参与执行的节点和结果差异；缺少多台主机时明确不通过“跨主机已部署”验收。
**Acceptance Scenarios**:
1. Given 本机单执行环境和同机多计算进程，When 处理固定数据，Then 对比产物与排序、耗时及进程身份，不将同机结果称作多机成果。
2. Given 将来多主机配置，When 预检查，Then 验证共享数据路径、依赖、网络与运行参数；必要条件缺失应明确失败。
3. Given 分布式配置，When 运行，Then 不被程序中的本地默认值悄悄覆盖。

### Edge Cases
中文夹技术名称、模型未配置、转换空或截断、原目标更改、旧缓存、名称别名、多对象目标、数字或代码遗漏、所有候选被筛掉、共享目录不可读、依赖未安装、同机多进程内存不足、不同分区浮点顺序差异。

## Requirements
### Functional Requirements
- **FR-001**: 保留中文原目标，并提供实际、版本化的跨语言查找解释与失败状态。
- **FR-002**: 原中文与转换后的目标均参与查找，避免修复英文召回后丢失中文来源。
- **FR-003**: 显式技术对象约束需要正文或标题证据；别名规则版本化，不为演示查询硬编码答案。
- **FR-004**: 目标解释、技术对象约束和原文推荐依据可在学习页面理解。
- **FR-005**: 译文记录处理器身份和有限质量检查；数字/代码完整性失败不发布为就绪，未知语义质量必须如实说明。
- **FR-006**: 不同目标处理器或翻译处理器版本不得混用旧任务与旧缓存。
- **FR-007**: 计算部署保留现有业务、权限、全文版本与个人历史规则；真实任务证据区分同机与跨主机。
- **FR-008**: 保留旧验收、冻结本次开发样例及原始结果；不得将合成样例或单机测量冒称独立学习效果或跨主机收益。

### Key Entities
目标解释、技术对象约束、译文处理器标识、质量检查、计算运行配置、共享路径检查报告、对照运行证据。

## Success Criteria
### Measurable Outcomes
- **SC-001**: 至少8组、覆盖至少4个计算机方向的双语目标完成真实处理，逐项报告结果；语言转换失败可见，不宣称所有主题已达标。
- **SC-002**: 固定的技术对象干扰用例全部遵守对象约束，无对象的普通目标不被错误要求产品名称。
- **SC-003**: 数字/代码遗漏及处理器升级的机制测试通过；至少一篇真实英文正文记录自动译文与质量信息，允许如实失败。
- **SC-004**: 相同固定输入在本地及本机独立计算进程上运行，给出一致性、资源和耗时证据；跨主机验收明确保持待资源。
- **SC-005**: 原计划与验收的每个主要需求都有状态、实现步骤或待决说明，不能以本阶段任务完成替代总体需求完成。

## Assumptions
[已验证：用户确认] 当前只有这一台电脑，不租用云机器、不调用付费服务。沿用中文学习工作台、显式已读、全文和RSS要求。
[方案] 本阶段执行总体新计划的第一批：修复跨语言入口、具体技术约束、译文质量基础和集群准备。更强模型的教学达标、多主题内容评测、主题关系可视化在后续依赖阶段继续；笔记、问答、视频/BV仍待产品决策。
[方案] 本地有界下载免费中文到英文模型；保留已有英中模型，不把新增规则或查询翻译称作通用语义理解。
