# Feature Specification: 多源全文、中文阅读与播客增量推荐

**Feature Branch**: `009-fulltext-podcast-learning`
**Created**: 2026-09-25
**Status**: 本阶段工程实现与验收完成；中文目标、媒体教学质量及学习收益未达产品验收终点
**Input**: 用户批准三条并行开发线：全文数据、翻译与音频处理、推荐与评价；主代理负责集成。承接根目录 plan.md 及 Feature 007/008。

## User Scenarios & Testing

### User Story 1 - 从真实多源全文发现学习资料 (Priority: P1)
有基础的计算机专业学生围绕自定目标，从万条以上计算机技术资料中得到可追溯推荐，而非只读摘要。
**Why this priority**: 原始资料的完整性决定后续比较和阅读是否有意义。
**Independent Test**: 独立采集、核验并导入至少 10,000 条有效全文，查看来源、领域、排除原因及来源链接。
**Acceptance Scenarios**:
1. Given 问答来源，When 导入，Then 保留问题、返回的全部回答、代码结构、作者及许可信息；回答不全的条目不计入合格全文。
2. Given 文档镜像，When 统计多源，Then 按原始提供方统计，内容重复不会重复计数。
3. Given 只有摘要的论文，When 导入，Then 不能声明全文或进入全文推荐；提取失败可见。

### User Story 2 - 自动阅读完整中文内容 (Priority: P1)
推荐入选的英文资料自动准备完整中文译文，保留原文；播客没有发布方文字稿时从音频生成全文。
**Why this priority**: 用户明确要求中文阅读，不应再单独触发翻译。
**Independent Test**: 使用真实本地模型完成一篇多段英文资料的翻译和一段公开音频的转写，记录耗时、模型与输出；测试双替身只用于失败路径。
**Acceptance Scenarios**:
1. Given 英文全文入选，When 翻译完成，Then 默认显示完整中文且可查看原文；相同版本复用译文。
2. Given 模型缺失、超时或部分输出，When 处理，Then 显示具体未就绪状态，不把半段文本当完整成功。
3. Given 超大、超长或非公开地址音频，When 下载，Then 有界拒绝且清理临时文件。

### User Story 3 - 订阅后获得相关的新播客推荐 (Priority: P1)
学生订阅 RSS 后看到全部订阅更新，并在节目与目标匹配时收到有依据的推荐；有阅读历史时进一步要求内容补充依据。
**Why this priority**: 这是用户要求的持续学习入口。
**Independent Test**: 重复轮询同一 feed，只处理和发布一次；无关节目显示在更新列表但不产生个人推荐；改变目标、退订、内容版本变化后不发布过时推荐。
**Acceptance Scenarios**:
1. Given 新节目无文字稿有音频，When 后台处理，Then 下载、转写、进入统一全文库、计算推荐、入选后自动翻译。
2. Given 用户有相关已读记录，When 产生主动推荐，Then 展示候选和历史原文位置及比较边界，不宣称用户一定不懂。
3. Given 用户无已读记录，When 推荐，Then 明确是目标相关推荐，不声称补充已学内容。
4. Given 小批新节目，When 更新索引，Then 复用旧文档特征；词汇变化或累计更新达到阈值时允许完整重建并记录原因。

### User Story 4 - 检验推荐解释及检索质量 (Priority: P2)
教师和开发者能区分真实外部检索标签、个人历史机制测试及模型输出质量。
**Why this priority**: 不用漂亮示例代替效果证据。
**Independent Test**: 固定独立测试查询及候选集后运行基线与实际推荐策略，公开指标、失败样例与适用边界，不以结果好坏更换测试查询。
**Acceptance Scenarios**:
1. Given 外部重复问题标签，When 评价，Then 只报告检索/重复匹配效果，不冒称学习收益或个性化标签。
2. Given 相同目标不同历史，When 比较，Then 解释真实候选片段与历史片段的区别，历史不足明确说明。

### Edge Cases
配额不足、网络中断、缺少回答/许可版本、版本更新、空转写、翻译截断、重复 RSS、用户退订、任务租约过期、无相关历史、未知新词和无结果均须显式处理。发布方文字稿优先；已有文本不重复转写。首次订阅默认最近三期，不无限回填。

## Requirements
### Functional Requirements
- **FR-001**: 万条级有效全文，多种原始内容提供方，记录原始 URL、采集时间、版本、语言、作者/许可及来源质量。
- **FR-002**: 完整中文阅读由入选触发，原文版本变化使旧译文失效；长文禁止静默截断。
- **FR-003**: RSS 自动下载和转写，处理可重试、幂等、有界，保留失败状态。
- **FR-004**: 全部订阅更新与个人主动推荐分开；通知受订阅、目标/历史版本、内容版本、中文就绪状态约束。
- **FR-005**: 个性化仅使用当前目标和显式已读历史，不推断掌握程度；比较字段必须有原文位置证据。
- **FR-006**: Spark 执行核心索引和推荐，增量复用与完整重建可追溯；Web 请求不启动 Spark。
- **FR-007**: 使用已有登录、CSRF、用户隔离、MongoDB，公开语料共享但个人记录及通知隔离。
- **FR-008**: 实际本地翻译/转写与独立检索评价有可复现运行证据；模型成本未确认前不调用付费服务。

### Key Entities
完整文档、来源采集清单、音频处理结果、版本化译文、增量索引、补充证据、个人推荐任务、RSS 节目、个人通知、固定评价查询。

## Success Criteria
### Measurable Outcomes
- **SC-001**: 至少 10,000 条完整、去重且属于计算机技术领域的文档，至少两个原始内容提供方；不足必须报告真实数量并保持该项未完成。
- **SC-002**: 至少一篇英文多段文章和一段真实音频完成真实模型处理，分别记录输入输出及版本，失败不得用假数据替代。
- **SC-003**: RSS 首次处理、重复轮询、缺模型/失败重试、用户隔离、退订、个人化通知和中文阅读流程通过测试；实际运行记录端到端阶段。
- **SC-004**: 固定外部查询、完整候选语料和标签上报告 nDCG/Recall/MRR 及无结果率，另列个人历史机制验证。
- **SC-005**: 记录万条规模 Spark 条数、作业/阶段、耗时、运行模式与资源；增量测试证明未重算不变文档的特征。

## Assumptions
[已验证：用户确认] 广泛计算机技术知识，Pandas 仅是样例。授权本地可逆开发及公开有界数据/模型获取。
[方案] 本地 CPU 模型作为免费可运行基线，不预先承诺教学级翻译或 ASR 准确率。模型缺失保持未就绪。
[方案] RSS 五分钟轮询、首次三期，通知在站内展示；处理耗时不等于即时完成。
[待确认] 多机资源、付费模型、教学质量阈值及更广泛视频/BV输入不阻止本阶段本地实现，也不算已完成。
