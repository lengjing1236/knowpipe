# Feature Specification: 规模验收、真实评价与跨来源关联

**Feature Branch**: `006-scale-evaluation-linking`
**Created**: 2026-09-19
**Status**: Ready for implementation
**Input**: 先完成万条有效数据验收和真实推荐评价，再实现播客与文献关联。

## User Scenarios & Testing

### User Story 1 - 可复现的规模验收 (Priority: P1)
[方案] 项目成员能从真实公开数据重跑挖掘并核对有效条数、失败、耗时及资源证据。
**Why this priority**: 补齐课程规模门槛。
**Independent Test**: 从冻结输入运行，核对实际持久结果与报告。
**Acceptance Scenarios**:
1. Given 两来源各100条链路已验证，When 扩展采集并处理，Then 主源有效记录不少于10,000且补充源非空。
2. Given 同一快照，When 重跑，Then 文档不重复且每次处理结果和统计可追溯。
3. Given 采集不足或处理失败，When 验收，Then 明确失败而非宣称通过。

### User Story 2 - 人工推荐效果评价 (Priority: P2)
[方案] 评审者对隐藏排序来源的文档进行相关性评分，项目成员获得个性化与对照排序的指标报告。
**Why this priority**: 区分排序实现与真实效果。
**Independent Test**: 两个学习任务完成候选盲标后，输出逐任务和平均指标；缺标签拒绝评价。
**Acceptance Scenarios**:
1. Given 至少两个学习任务和固定数据，When 导出候选，Then 标注页面不显示算法来源并提供原文、任务说明和0–3分规则。
2. Given 完整人工标签，When 导入，Then 得到 Precision@10、NDCG@10 及差值，保留快照和评审信息。
3. Given 未标注或不完整标签，When 导入，Then 拒绝发布业务效果结论。

### User Story 3 - 从播客找到相关文献 (Priority: P3)
[方案] 用户在已订阅节目的每个片段下看到最多三篇关联文献及关联词，打开原文继续学习。
**Why this priority**: 让已有多来源数据形成学习链路。
**Independent Test**: 已知相关/无关文本的排名合理，未订阅用户不可读取，内容变化时旧结果不展示。
**Acceptance Scenarios**:
1. Given 可读片段与文献，When 关联处理成功，Then 展示最多三条有共同词的文献并可打开详情。
2. Given 无共同词或尚未处理，When 阅读，Then 明确暂无关联，不填充随机内容。
3. Given 处理失败或输入更新，When 阅读，Then 不展示不完整或失效的关联。

### Edge Cases
[方案] 处理来源限流、内容重复、空词表、同ID不同来源、短推荐列表、缺失标签、越权读取、已删除文献、重跑失败与输入超限。使用自动回归覆盖这些关键边界。

## Requirements

### Functional Requirements
- **FR-001**: [方案] 保存原始快照、内容指纹、来源、质量计数、运行参数、代码版本、计算日志、耗时与内存观测。
- **FR-002**: [方案] 验收基于同一成功批次的实际主源有效结果，至少10,000条；补充源不计入门槛。
- **FR-003**: [方案] 支持从本地冻结快照重跑；不覆盖用户现有演示数据。
- **FR-004**: [方案] 采用现有推荐与对照算法，转为文档去重后的排序；保留学习任务与画像快照。
- **FR-005**: [方案] 人工标签不得由系统自动填充；盲标候选顺序固定且隐藏算法归属，导入检查候选完整性和评审信息。
- **FR-006**: [方案] 每项任务及总体报告包含两种排序的指标、样本数和差值；负提升允许且如实展示。
- **FR-007**: [方案] 跨源关联使用统一的文本比较标准，返回文献出处、片段编号、分数、关联词与处理版本。
- **FR-008**: [方案] Web只读取已完成结果，复用订阅授权；失败不替换成功版本，内容变化使旧关联失效。
- **FR-009**: [方案] 明确无结果原因与输入规模上限，不将词汇关联描述为事实核验或跨语言语义理解。

### Key Entities
[方案] 数据快照、规模验收运行、学习任务/画像快照、盲标候选包、人工评审、评价报告、关联运行、片段—文献关联。

## Success Criteria

### Measurable Outcomes
- **SC-001**: [方案] 一个真实成功批次含不少于10,000条有效主源与非空补充源，报告与持久化计数一致。
- **SC-002**: [方案] 至少两项真实学习任务的人工评价可复算，两种方法的前10候选全部获得人工标签。
- **SC-003**: [方案] 每个可关联片段展示不超过3条可追溯文献；未授权请求和失效关联均不泄露内容。
- **SC-004**: [方案] 自动测试覆盖失败与空结果，真实数据完成关联运行和网页/API验收。

## Assumptions
[方案] 复用现有技术栈和本机计算环境，独立实验库保护已有演示。默认学习任务为 Spark 数据处理与 Linux 服务运维，由用户确认或替换。人工标注由真人完成；准备工具和候选后等待真实标签时可继续独立的关联实施，不把评价标记完成。首版提供播客到文献单向关联，手动离线刷新；不增加ASR、多机集群或永久云部署。
