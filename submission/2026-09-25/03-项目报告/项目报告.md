# 基于Spark与MongoDB的多源计算机技术资料分析与个性化推荐Web系统

项目报告 · 2026-09-25

项目名称：Knowpipe。源码仓库：https://github.com/lengjing1236/knowpipe 。本报告依据当前源码、Spec-Kit规约及已保留验收结果；本次提交版本与远程推送状态见提交包源码清单。

## 1. 做什么、目前做到什么

系统面向有基础的计算机专业学生：输入中文技术学习目标，从多个来源的技术全文中查找相关材料，参考主动已读记录展示可能的阅读补充，再提供中文阅读。来源包括技术问答、官方文档、教程等；播客通过RSS发现与音频转写进入同一文本流程。

目前已经实现真实Web、MongoDB、独立worker和单机Spark链路；目标、正文版本、主动已读、推荐状态、原文依据、自动全文翻译和RSS处理都有对应代码。既有10,215篇背景用于真实评价。**当前能运行的功能与推荐质量达标是两件事：011核心质量验收未通过，本次演示不宣称已解决所有推荐与翻译问题。**

本次012录屏版使用12篇原生中文官方资料（Python 7篇、Django 5篇），完整导入独立`knowpipe_demo012`数据库，运行真实推荐、阅读和显式已读重算；地址为`http://127.0.0.1:8019`。真实网页已完成目标→推荐→中文全文→主动已读→重算；已读数为1，修订号2的新任务就绪，已读Django事务资料被排除。重算语义状态为partial，首轮仍有偏题，不能把工程闭环写成推荐质量通过。该子集用于展示流程，与10,215篇背景质量实验分别说明；中文原文直接阅读不冒充翻译成功。

## 2. 四层架构

| 层次 | 模块与职责 |
| --- | --- |
| Web交互层 | Flask页面与JS，目标输入、材料列表、原文/中文阅读、主动已读和处理状态 |
| 业务层 | 会话鉴权、目标/历史修订、任务调度、worker租约、RSS订阅和通知门控 |
| 数据管理与挖掘层 | MongoDB全文/用户/任务/结果/缓存、来源与版本管理、有界语义比较和选择规则 |
| Spark大数据处理层 | 全文索引、全库词汇召回、版本历史筛选、特征聚合、覆盖/补充/去重评分 |

请求先保存业务意图，由独立worker执行Spark，再回存结果供页面查询；长任务不由一次HTTP请求承担。模型提供相关性、蕴含、翻译或ASR能力，不能直接生成结果列表后声称完成Spark挖掘。

## 3. 技术选型及理由

- **MongoDB**适合不同来源字段不完全一致的长文档，能保存原文、状态、版本和用户记录；数据库操作与文件快照分工明确。
- **Spark**真实承担文本特征、召回与自定义评分。本次只有一台电脑，使用local模式；不是跨主机集群。
- **Flask与独立worker**沿用现有页面/鉴权并分离后台计算，便于在课程周期内建立可运行闭环。
- **词汇候选＋有界语义比较＋自定义选择**兼顾本机资源与解释需求。自定义规则结合目标相关性、历史覆盖、候选补充及列表重复；借鉴MMR/覆盖思想，不声称模型和算法理论均为原创。
- **可配置翻译与ASR provider**解决阅读和输入问题。011已测本地免费候选存在误译；012改为免费远程`bigmodel-free`模式，失败时不可用，不启动本地模型或收费回退。已对3个官方技术段落及1个中文目标发起4次真实远程调用，均返回HTTP 401鉴权失败，未获得译文，尚不能验收远程质量。

多主机Spark主要可能改善更大数据量下的容量、并行吞吐与任务恢复，不能使错误推荐自动正确。单机和分布式执行相同算法时，产品含义原则上应一致；先确认算法有效再扩大部署，能避免把更多机器用于放大错误。

## 4. 核心功能与实际流程

用户保存目标后，系统从全文索引召回候选，筛掉错误技术对象；结合真实已读版本，计算正文相关性、重合与可能补充。Spark聚合这些特征并输出最多3项，同时保留候选和历史原文位置。已读变化后可发起新任务；已读只是阅读记录，不是掌握标签。

入选英文材料自动准备全文中文，保留原文及段落对照，处理失败明确显示。新RSS节目获取文字稿或完整音频ASR，正文进入同一推荐流程；只有符合当前用户目标和历史补充条件、中文就绪且订阅有效的材料才允许通知。

系统能辅助筛选、组织、比较资料；不能可靠证明用户未知、已掌握、学习能力提升或材料事实绝对正确。不同来源并不天然互补，翻译字数完整也不意味着技术含义正确。

## 6. 与初版方案的差异及原因

| 初版方案 | 当前调整 | 为什么调整 |

| 关键词/主题簇映射known/new/refine等类别 | 目标相关性＋版本化已读材料比较 | 关键词出现不代表掌握，换词不等于新知识，需要正文事实支持 |

## 8. 下一步改进

先把相关性与补充判断分开验收：让材料正文直接回答目标，再对相关陈述寻找可比较的历史证据；对无法证实的补充保持不确定。随后验证免费远程翻译的关键术语、条件和顺序，并让真实页面完成阅读与已读重算。完成这些之后，再补全基线和三分支通知对照；只有质量达到门槛才开展跨主机部署和扩大语料。这样每项工作都能对应实际用户价值，而不只增加功能数量。
