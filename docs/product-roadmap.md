# 功能方向：让播客变成可追溯的学习资料

[已验证] 课程 PDF 的五个评分维度为：底层处理架构 20%、数据管理 20%、挖掘与创新 20%、系统完整性 25%、规范与过程 15%。PDF 提到真实集群优于单机，并未要求所有项目必须先上集群；你的公网访问需求独立成立。

[已验证] 本次已实现的业务主线：订阅公开 RSS → 新节目去重 → 获取公开文字稿/补充文字稿 → Spark 分段分析 → 用户站内通知。自动音频转写尚未实现。

## 推荐的后续功能优先级

| 优先级 | 功能 | Spark 做什么 | 答辩能展示什么 |
|---|---|---|---|
| P1 | 跨节目主题趋势 | 按发布时间窗口聚合关键词、主题频率及环比，统一模型版本后比较 | 一周内哪些技术话题升温、依据来自哪些节目 |
| P1 | 播客与技术文献关联 | 在统一词表/模型中召回相关文档，再用相似度排序 | 听到某个观点后查看相关论文/问答；相关性不代表事实核验 |
| P2 | 基于已知主题的个人学习摘要 | 结合画像计算新增关键词比例、主题相关度与已读惩罚 | 同一期节目对两个用户的学习重点为何不同 |
| P2 | 自动音频转写与时间轴 | ASR 负责音频变文字；Spark 负责后续文本加工 | 从音频定位到关键词片段，保留转写来源与误差说明 |

[方案] 先实现一项能给出对照数据的分析功能，再扩展其他功能。中文 ASR 需要明确硬件/耗时/预算；订阅平台有时不开放 RSS 或文字稿，应以实际节目验证为准。邮件/即时通信推送需要另行授权、配置发信方和收件范围；当前只提供站内通知。

## 用简单语言理解底层

TF-IDF 相当于找出一段话里“对这段内容特别有代表性”的词；所有段落都出现的词通常没那么有区分度。KMeans 按词语特征把内容分组，主题编号本身不是自然语言标签。余弦相似度比较两段内容的词语方向是否接近，它不判断两段话是否真的正确。

Spark 把这些计算组织成可分发的任务。数据小时启动成本可能比普通 Python 高；数据量、分区和计算证据才是解释选择 Spark 的依据。MongoDB 保存不同来源的半结构化文档、用户关系、任务状态和批次索引。
